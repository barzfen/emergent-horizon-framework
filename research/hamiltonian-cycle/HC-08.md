# EHF-HC-08 · Exact degree-group joins

**PROVED.** Grouping realised records by degree and indexing right-child profiles by the degrees needed at forgotten vertices gives exactly the same join as checking every record pair. The index can apply the remaining degree limits by bitset intersection. Every surviving pair still passes through the cycle and matching logic.

**COMPUTATIONAL.** All four implementations produced identical tables at 27,596 intermediate joins in the small-graph audit. On the fixed sorted-edge plan for $K_9$, the indexed version took about 11 ms versus 278 ms for the original scan, with the same 4,815 matching checks. The narrower plans left less excess work for the index to remove.

## Join realised records by exact degree

Use the degree and matching records from [HC-05](HC-05.md#what-passes-through-a-boundary), with the fixed decomposition plans from [HC-07](HC-07.md#choosing-fewer-candidates). For a join let $B_L,B_R$ be the child boundaries, $B$ the parent boundary, and $F=(B_L\cup B_R)\setminus B$ the vertices being forgotten. Extend each child's degree profile by zero at vertices absent from its boundary. The required final degree $d(v)$ is one at a terminal and two elsewhere.

Two realised profiles $a,b$ can be considered for a matching join exactly when

$$
a_v+b_v=2\quad(v\in F),\qquad a_v+b_v\le d(v)\quad(v\in B).
$$

Both terminals stay on the boundary. At a retained vertex present on only one side, the degree cap already holds in that child. A vertex internal to a child has no available edge in the sibling piece or outside the parent, so it is absent from the active join boundary. These facts let the comparison use only $F$ and the shared retained vertices $S=B\cap B_L\cap B_R$.

The grouped join puts all matchings with the same realised profile in one group. The degree predicate and summed output profile are constant across the product of two groups. If their profiles pass, apply the exact matching join to each pair of matchings from the groups. The number of matching checks is therefore $\sum_{(a,b)\ \mathrm{compatible}} |G_L(a)|\,|G_R(b)|$. A cycle can still disqualify a matching pair after the degrees pass.

### Index the right profiles

Give each realised right profile a bit position. A hash table maps its vector on $F$ to the bitset of profiles with that vector. At each $v\in S$, also store the right profiles with degree zero and those with degree at most one. For a left profile $a$:

1. Look up the right-profile bitset keyed by $(2-a_v)_{v\in F}$.
2. For each $v\in S$ with $a_v>0$, intersect it with the bitset for degrees at most $d(v)-a_v$. For $a_v=0$ the cap already holds.
3. Iterate the right profiles named by the remaining bits and apply the grouped matching join.

The lookup gives all and only the right profiles that satisfy the forgotten equalities. The intersections enforce every remaining degree cap. Thus the bits name exactly the compatible groups. Each of their matching products sees the same cycle checks and emits the same parent records as the original scan. This construction uses measured child records, so the independently assignable degrees that caused overcounts in HC-07 do not enter.

## Checks and timing

The small-graph audit used McKay's connected simple graph catalogues for orders two through six, with 142 graph shapes and 1,933 terminal pairs. For each pair it used a balanced split of sorted edges and a split that joins one edge at a time. At every intermediate join it compared the entire unreduced output table and the count of degree-compatible record pairs. There were 27,596 identical intermediate tables and 3,866 terminal decisions agreeing with independent whole-graph path enumeration. [McKay's graph catalogue](https://users.cecs.anu.edu.au/~bdm/data/graphs.html)

The timing test used all ten HC-07 queries and held the decomposition fixed while varying the join. It used the sorted, all-start width, and sampled width plans with compact matching reduction in each case. The four implementations were:

- **Record scan.** The original per-record join, forming a degree map for each record pair.
- **Vector scan.** Pre-align the degree tuples and scan every record pair. This isolates the effect of using aligned degrees.
- **Grouped.** Align degrees and apply one degree test per group pair.
- **Indexed.** Find the compatible groups by lookup and bitset intersection.

All 120 configurations agreed with the independent oracle and kept the same state counts and matching-check counts within each fixed plan. Reported times are medians of nine CPU-time runs on CPython 3.12.14 and an AMD EPYC 9V45. The plan was built before timing. Matching caches started empty in each timed solve. These are solve times for fixed plans, including index construction when used.

The index counts cover hash lookups and executed bitset intersections. The solve times also include building the bitsets, enumerating emitted group pairs, and performing the exact matching joins. The indexed mode had the lowest median for all ten sorted plans, four of ten all-start width plans, and five of ten sampled width plans. In the 12-vertex ladder's all-start plan, grouping leaves the degree-check count at 72 and the index setup costs more than it saves. On the sorted $K_9$ plan the index was about 25 times faster than the original scan and about 12 times faster than the aligned vector scan. Both comparisons keep the same graph, state records, plan, and matching reduction. The timings describe these prototype workloads. ## Reproduce

Run from the repository root with Python 3.12 and its standard library. The [verifier](verify_hc_08.py) prints all 30 fixed plans and four modes and checks every answer. The optional catalogue audit uses McKay's graph6 data under CC BY 4.0, retrieved on 17 November 2026. In ascending order from two through six the downloaded files concatenate to SHA-256 `aac6ee79a87ae807bd036015ff9970ec45f64815ab0be68ac6c1fd35a3515c81`. [Data licence](https://users.cecs.anu.edu.au/~bdm/data/)

```sh
python3 research/hamiltonian-cycle/verify_hc_08.py --repeats 9

catalogues=$(mktemp -d)
for order in 2 3 4 5 6; do
    curl -fLsS "https://users.cecs.anu.edu.au/~bdm/data/graph${order}c.g6" \
        -o "$catalogues/graph${order}c.g6" || exit
done
python3 research/hamiltonian-cycle/verify_hc_08.py --catalogue "$catalogues"/graph[2-6]c.g6
```

The next test is whether the realised child table sizes can select between a scan and an index cheaply enough to keep the advantages on both small and large joins. This probe was developed with AI assistance.
